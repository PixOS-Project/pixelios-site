# Release note 2026-11-15

**Last verified: 2026-11-16.** Release of the PixOS repositories (code, docs and this site) for the 2026-11-15 state. Every number below is from the maintainers' run logs
(run labels in `code`), observed on hardware unless marked otherwise. Full tables: [Status](STATUS.md).

**Now working:** GPU acceleration, Wi-Fi with real internet, Bluetooth, and touch.
**Not working yet:** audio playback.

Disclaimer: AI was used heavily to make this run on Pixel 6a; it is based on [ios-sweet](https://github.com/dipa-studio/ios-sweet).
See [AI-driven development](AI_DEVELOPMENT.md). This is research code for a spare phone, not a daily-driver operating system.

## What works

| Area | Result | Run |
|---|---|---|
| GPU | Smooth UI at about 50 fps with the GPU at its lowest clock (150 MHz): 600 s navigation bench, rendered 50.6 / 50.6 fps pooled, slowest step 48.4 / 48.6 (bars 50 / 45 met on both boots), no reset, about 37 min uptime each | `155b`, `8177` |
| GPU, frame pacing | One frame per vsync with the hold capped at one tick: all panel presents 51.2/s (49.5 to 49.9 without it) | `18e1` |
| Wi-Fi | Joins WPA2 networks and gets real internet: address, route, DNS, HTTPS (pixnet 9/9, link down 0). TCP download 285.4 / 188.1 Mbit/s average, upload 97.1 / 97.0 Mbit/s under the full bench load (host journal) | `155b`, `8177` |
| Bluetooth | Pairs and connects devices; a headset was paired and connected by hand in Settings (Simple Pairing Complete status 0, Link Key Notification, 3 connections complete). The firmware load no longer spins a core for 41.5 s | job 1308 (demo boot), `d9a3` |
| Touch | A real finger on the demo boot: 5791 touch interrupts, 0 empty, 0 storm, interrupt mode, events with raw coordinates. Unlock and app open were done by hand on the maintainer's own recording | job 1308 |
| iOS | Boots to lock and home screen; Settings and MobileSafari (launched 6 times in the demo log; page load itself not logged) run | job 1308, `gputest-surffail-b` |

## Configuration of these numbers

5 of the 8 CPU cores run. CPU A76 at 1663 MHz and X1 at 1826 MHz as static rows, GPU 150 MHz (no boost), memory 1352 MHz; the 600 s
bench ran with full Wi-Fi load. More CPU did not help: A76 at 1836 MHz gave rendered 50.5 fps (run `fede`). A boot needs the PixOS shim
(loaded with `fastboot boot`) and the iOS `userdata` root, as described in the [build docs](https://github.com/PixOS-Project/pixelios-kernel/blob/main/docs/BUILD.md).

## Known issues

- **Drawn presents: 49.0 per second** with the pacing fix (run `18e1`), against the bar of 50: **not met yet**. Drawn presents without the fix are about 47.5 per second (estimated, not measured); all panel presents were 49.9 and 49.5 without the fix (`155b`, `8177`) and 51.2 with it. About 1.8 per second of swaps are lost when a third swap lands inside the hold.
- **No audio playback.** No speaker driver; a headset pairs and the A2DP stream configures, but iOS never sends Start (`bt-va3`).
- **UDP download loses packets under heavy load:** 27.3 % and 39.5 % in the two bench boots, 2.4 % in one run after the bench, 0 in others (`155b`, `8177`, `979b`). Cause not found.
- **`lskdd` restart loop:** the iOS daemon exits about once a second all boot long (14 to 16 ms each); cause not found, not disabled.
- Cold start counts in the bench (first 13 s cost about 0.17 pooled fps); about 593 MB of UFS writes in 10 min from an unknown writer.
- Spotlight band and the search magnifier glyph (2026-11-11 list, not re-checked); "Weak Security" label on the WPA2 network.
- Not yet: cellular, camera, sensors, Face ID / fingerprint, sleep/wake.
